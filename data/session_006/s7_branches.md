2. **The realised-share check** (Appendix D, step 2). A run is resumed only after its training call has ended, as shown by the call id printed at launch. If its log then holds fewer than 28,000 samples, it was cut short: it is resumed with `--resume` on the same configuration, with no harness code committed or deployed since its launch, then collected and checked again. The caught-failure count is judged only on a log of exactly 28,000 samples. [Work] stops before that run's `record`, [process note removed] if a resume is refused or adds no samples, if the log holds more than 28,000 samples, or if a 28,000-sample log holds other than 2,763 caught-failure draws for an A1 run or 5,595 for an A2 run. Every resumed run is reported with the step it resumed from.
3. **A readout fault** (Appendix D, step 3). If `record` or `read` stops with an error, it is run again, since `read` resumes from cache. If the same fault repeats, it goes to [author 5] alone. [author 5] extracts only the final traceback from the console output, opens nothing under `results/session_006/adv_*` or `.cache/session_006/adv_*`, never opens `readout_log.txt`, and reports only the exception and where it was raised, with no reading. A fix that would change committed code is reviewed and approved before it is made.
4. [process note removed] A stop before a rerun for any reason is a pause, not an outcome: every unread file stays unread, and `describe` is not run.
5. **A rerun that cannot finish in one working period.** It stops at one of two points: just after a run's `--collect`, or just after an attempt's seal, never during a `record` or a `read`. Nothing is then touched, the cache included, and work resumes from that point. A1's readings stay sealed across the break until A2's seal is committed ([further-run rule 7]). Since no stop point lies between a run's `record` and the seal, A2's first `record` starts only if A2's seal can be reached. Training runs already spawned are left to finish and are collected afterwards.
